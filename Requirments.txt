2. Technical Requirements Specification
2.1 Core System & Data Persistence
   * Flat-File Storage Engine:
   * All boards, columns, cards, and system preferences must persist in local JSON/YAML files.
   * Data Integrity (Added Requirement): Implement file locking and atomic write operations (e.g., write to temporary file, then rename) to prevent file corruption if tasks are written simultaneously via UI and API.
   * Backup & Disaster Recovery:
   * Automated Backups: Configurable cron schedule (default: Weekly). Backup files stored in a designated /backups directory on the host machine.
   * Naming Convention: Datetime-stamped filenames (e.g., kanban_backup_2026-07-25_153000.json) to create a clear chronological timeline for restoration.
   * Manual Management: UI buttons in Settings to trigger instant manual backups or select from a list of historical backups to restore.
2.2 Authentication & User Management
   * Single-User Access Control:
   * Password-protected login screen.
   * Session management using JWT or encrypted cookies so login state persists across page refreshes.
   * Single global configuration file storing the hashed application password.
2.3 Board & Tab Architecture
   * Tab Navigation System:
   * Top navigation bar using a tab-based UI to switch between boards (e.g., Personal Tasks, Development, Vacation Planning).
   * A + button located next to board settings to open a pop-up modal for creating new boards.
   * Board Header & Information:
   * Displays Board Name, Description, and Live Date/Time clock at the top left.
   * Top-right includes a Gear Icon for board-specific settings and configuration modals.
   * Column Management:
   * Add, rename, reorder, or delete category lanes/columns per board.
   * Default column template provided upon new board creation: To Do, In Progress, Done.
2.4 Visual Customization, Themes & ADA Compliance
   * Accessibility & Contrast:
   * All card, column, and background color pairings must meet WCAG 2.1 AA (ADA compliant) contrast ratios (minimum 4.5:1 for standard text) to guarantee legibility.
   * Theme System:
   * Mode Toggle: System preference sync, explicitly toggleable to Light Mode or Dark Mode.
   * 20 Color Palette Combinations: Presets featuring fun, vibrant colors for tags and cards that stay high-contrast against background themes.
   * Persistent Board Zoom Levels:
   * Each board features a visual zoom control slider/pallet (e.g., 75%, 100%, 125%) to adjust card size and visible lanes.
   * Zoom level setting is saved per board in the file configuration so it remains persistent across user sessions.
2.5 Card Structure & Drag-and-Drop
   * Card Metadata:
   * Subject (Title)
   * Description (Rich text or Markdown supported)
   * Created Date (Auto-generated timestamp)
   * Due Date & Time
   * Priority level & visual color-code tags.
   * Sorting & Ordering Rules:
   * Manual Drag-and-Drop: Intuitive card reordering within columns and between columns.
   * Auto-Sort Engine: Toggleable per column/board. When enabled, automatically sorts cards by Priority or Due Date (highest priority/earliest due date at the top).
   * Mobile Responsiveness:
   * Layout dynamically responds to mobile screen widths (collapsing columns into horizontally scrollable or accordion views on phones).
2.6 Notifications & Alert Engine
   * Integration Channels:
   * SMTP Email: HTML formatted email template displaying upcoming/overdue tasks with direct action links.
   * Discord Webhooks: Structured Discord embeds for instant task alerts.
   * Configurable Alert Thresholds:
   * Daily Digest: Single summary notification sent daily containing tasks due within the current week.
   * Card-Moved Ping: Real-time Discord alert dispatched when a card lands in a board's configured notify lane.
2.7 REST API & Workflow Integration (n8n / Webhooks)
   * API Endpoints:
   * GET /api/boards - Fetch list of all active boards and summary meta.
   * GET /api/boards/{id} - Fetch complete schema, columns, and cards for a board.
   * POST /api/tasks - Create a new task programmatically via external tools (e.g., n8n workflows).
   * PUT /api/tasks/{id} - Update task status or move across columns.
   * API Security (Added Requirement):
   * Bearer Token / API Key authentication header for external workflow requests.
3. Recommended Additions (Gaps Identified)
To keep the app smooth and usable without a full database, consider these extra features:
   1. Search & Filter Bar: A quick search input on the top bar to filter cards across columns by keyword, tag, or due date.
   2. Archived / Completed Card Handler: To prevent flat storage files from growing uncontrollably over months, add an "Archive" state for completed cards so they don't clutter active column renders.
   3. Webhook Trigger on Card Move: Send an outgoing webhook event whenever a card moves to a specified lane (e.g., moving a card to Done automatically pings Discord or runs an n8n workflow).
